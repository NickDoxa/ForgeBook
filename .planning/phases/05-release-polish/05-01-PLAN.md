<threat_model>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| build-gradle → released jar | Version-string mismatch between Gradle and the tag applied to the git commit would produce a jar named for a version that was never tagged. |
| mods.toml → Forge mod-list UI | Forge parses `credits` and displays it; mis-formatted TOML would break mod loading for all users. |
| assets/forgebook/textures/gui/logo.png → future in-chat renderer | A later v2 renderer may `ResourceLocation`-load this path. A missing or corrupted PNG would cause a render crash in that future phase. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-05-01-01 | Information Disclosure | mods.toml | mitigate | `credits` attribution is intentional public disclosure (jsoup MIT "permission notice shall be included" is satisfied by in-manifest credit). No secret disclosure — API keys live in forgebook-server.toml, not mods.toml. |
| T-05-01-02 | Denial of Service | mods.toml parse | mitigate | Validate TOML syntax by running `./gradlew build --no-daemon` after the edit — build fails fast on malformed TOML. Acceptance criteria gate on green build. |
| T-05-01-03 | Tampering | logo.png placeholder | accept | Placeholder is 1×1 transparent PNG — zero information content to tamper with. Real branding is user-supplied post-release. |
| T-05-01-04 | Elevation of Privilege | build.gradle version bump | accept | `version = '1.0.0'` change does not affect runtime permission logic (OP gate is in Authorizer, not Gradle). Release tag mismatch is a process issue mitigated by tag-then-build discipline, not code. |
| T-05-01-05 | Repudiation | jsoup attribution | mitigate | MIT license requires attribution; `credits` field + THIRD_PARTY_NOTICES.md together give double-attribution (manifest + repo). Repudiation risk ("we stole jsoup") is neutralized. |
| T-05-01-06 | Spoofing | logoFile location | mitigate | Explicitly verified `logoFile="logo.png"` stays at JAR root (not moved to assets/forgebook/). Forge silently fails otherwise — would display no logo, appearing as if the mod were broken or spoofed. Acceptance criteria greps for exact path. |

</threat_model>
