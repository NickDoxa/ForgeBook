<objective>
Complete the REL-02 server-side i18n refactor: replace every user-visible `Component.literal("English prose")` call in the 7 target Java files with `Component.translatable(key, args?)` calls that reference the 26 new keys shipped in Plan 05-03's en_us.json. This includes the sealed-record refactor for `Authorizer.Denied` and `AiDispatcher.Error` using Option A (split fields — keep `String humanReadable` for wire/audit, add `Component feedback` for command surface) per PATTERNS.md L32-46.

Purpose: Phase 3 shipped ~20 English literals in command-feedback paths. These render correctly in `en_US` clients but bypass Minecraft's translation layer — a French-client player would see English. REL-02 closes the gap. Option A (split fields) is chosen over RESEARCH's Option C recommendation because PATTERNS.md's architectural analysis shows `ChatErrorPacket.humanReadable` is a wire-format String that cannot be broken without bumping the SimpleChannel protocol version. Option A splits the two concerns cleanly: wire stays String (no break), command surface gets Component (new capability).

Output: 7 modified production files + 6 modified test files. `./gradlew build test` green.
</objective>

<wire_format_guarantee>
**The wire is a String.** `ChatErrorPacket.humanReadable` is defined as `String` (see ChatErrorPacket.java) and encoded via `buf.writeUtf(humanReadable, 512)`. Changing it to `Component` would require a codec rewrite AND a SimpleChannel protocol version bump (risk of client disconnect during rolling updates).

**The refactor (Option A) avoids this:** Keep `String humanReadable` on both `Authorizer.Denied` and `AiDispatcher.Error`. Add `Component feedback` as a second field. Wire path reads `.humanReadable()`; command-surface path reads `.feedback()`. Zero wire break.

**Do NOT** refactor `ChatErrorPacket` in this plan. Do NOT change the `writeUtf`/`readUtf` call shape.
</wire_format_guarantee>
