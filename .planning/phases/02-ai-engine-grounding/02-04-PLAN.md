<objective>
Build the CurseForge integration that fetches modpack metadata once at server startup and caches it for use by the system-prompt builder (Plan 06) and `GetModpackContextTool` (Plan 05).

Purpose: Satisfies CF-01 (one-shot fetch with `x-api-key`), CF-02 (strict optional, never errors), and CF-03 (no per-message calls). Provides the `ModpackContext` data carrier that the system prompt enriches with modpack name + summary so the agent can answer cross-mod-synergy questions.

Output: `ModpackContext` record, `CurseForgeClient` static fetcher (raw `HttpClient` + Gson), `ModpackContextCache` volatile holder, and JUnit 5 tests covering 200, 401, 404, 5xx, network error, and malformed-JSON paths.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Server → api.curseforge.com | Outbound HTTPS to a trusted third-party API. Auth header (`x-api-key`) carries a SERVER-tier secret. Response body is parsed as JSON into typed records. |
| ConfigSnapshot → CurseForgeClient | Operator-controlled config (`curseforge_modpack_id`, `curseforge_api_key`) crosses into the integration layer. Modpack ID is appended to URL path; API key is sent in a header. |
| api.curseforge.com response → SystemPromptBuilder (downstream, Plan 06) | Untrusted third-party text (`summary`) flows into the system prompt. Prompt-injection risk is mitigated downstream via PromptFraming (Plan 05) — out of scope here, but called out for traceability. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-04-01 | Information Disclosure | `CurseForgeClient` log statements | mitigate | Logger never logs the `x-api-key` header value or `snap.curseforgeApiKey().raw()`. WARN messages reference only `snap.curseforgeModpackId().get()` (operator-public) and `resp.statusCode()`. Phase 1's `ApiKeyScrubFilter` (extended in Plan 01) catches any accidental leak in stack traces. |
| T-02-04-02 | Denial of Service | `CurseForgeClient.fetch` blocking the calling thread | mitigate | Hard `Duration.ofSeconds(15)` `.timeout(...)` on `HttpRequest`. Caller (Plan 06 `ServerStartedEvent` listener) wraps in `CompletableFuture.supplyAsync(..., AiExecutor.get())` with `.orTimeout(10, SECONDS)` so the server-startup thread is never blocked by CurseForge slowness. |
| T-02-04-03 | Tampering | Modpack ID injected into URL path | mitigate | `snap.curseforgeModpackId()` is `Optional<String>` from ForgeConfigSpec — Forge config validation already constrains the value. The modpack ID is appended directly to a fixed `https://api.curseforge.com/v1/mods/` prefix; even with adversarial input the worst case is a 4xx response which is silently swallowed (CF-02). No path traversal possible — host is fixed by `URI.create`. |
| T-02-04-04 | Spoofing | Untrusted/spoofed CurseForge response | accept | TLS via `java.net.http.HttpClient` defaults provides certificate validation. Operator-supplied API key authenticates THE CALLER not the response. We accept the response at face value — worst case is bad modpack metadata in the system prompt, which is no different from any other operator-controlled config string. Downstream PromptFraming (Plan 05/06) treats the summary as untrusted input regardless. |
| T-02-04-05 | Repudiation | No audit trail for CurseForge calls | accept | Single call per server start + per `/forgebook reload`; the WARN log on failure is sufficient operator visibility. Full audit trail not required by REQUIREMENTS. |
| T-02-04-06 | Elevation of Privilege | Unbounded JSON parsing → resource exhaustion | mitigate | `summary` is defensively truncated to 500 chars via `SUMMARY_CAP` constant in `parseResponse`. Gson with default settings rejects pathological JSON (depth limits, etc.). Response body size is implicitly bounded by CurseForge's API behavior (responses are O(KB) not O(MB)) and the 15s timeout. No JSON-bomb mitigation needed beyond defaults. |
| T-02-04-07 | Information Disclosure | API key leakage via thrown exception | mitigate | `fetch` wraps the entire request in `try/catch (Exception e)` and logs at WARN with `LOG.warn("CurseForge fetch failed; skipping modpack context", e)`. The `e` may contain the URL but never the header value (java.net.http does not include request headers in its exception messages). `ApiKeyScrubFilter` (Plan 01 extension) provides defense-in-depth. |
</threat_model>
