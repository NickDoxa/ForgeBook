    ### Test 1 — Inventory-button injection (UI-01, UI-02)

    - Press E to open Inventory.
    - VERIFY: A 20×20 button labeled "F" appears at `leftPos + imageWidth + 4, topPos + 4`
      (just outside the inventory's right edge, near the top).
    - VERIFY: Hovering the button shows tooltip "Ask ForgeBook".
    - VERIFY: The button does NOT overlap the recipe-book toggle tab (which sits INSIDE the
      inventory at the inventory's native +48, +79 offset — plenty of clearance).
    - Record: PASS / FAIL + screenshot path in `04-HUMAN-UAT.md`.

    ### Test 2 — ChatScreen opens, inventory visible behind (UI-02)

    - Click the "F" button.
    - VERIFY: ChatScreen replaces the inventory at the widget-focus level but the inventory
      frame (hotbar, armor slots, crafting grid) is STILL VISIBLE behind the chat panel.
    - VERIFY: Chat panel renders centered-horizontal on wide screens OR stacked / full-width
      on narrow screens (<320 GUI pixels).
    - VERIFY: Panel shows "Ask about a mod, an item, or what you're looking at." empty-state
      copy when conversation is empty.
    - VERIFY: EditBox with placeholder "Type your question…" at bottom of panel; "Ask" button
      to its right.
    - Record: PASS / FAIL + screenshot.

    ### Test 3 — Optimistic user bubble + pending state

    - Type "hello" in the input.
    - Press ENTER (or click "Ask").
    - VERIFY: User's message appears IMMEDIATELY as a right-aligned bubble with "You" label
      (white, bold).
    - VERIFY: Input becomes greyed / uneditable.
    - VERIFY: "Thinking…" indicator appears with animated dot cycler.
    - Record: PASS / FAIL + note animation cadence (should be ~500ms per frame).

    ### Test 4 — Assistant reply lands + pending clears (REQUIRES API KEY — else SKIP)

    - Wait for server reply (typically 3-10 s with Haiku).
    - VERIFY: Assistant bubble appears on the LEFT with "ForgeBook" label in accent color
      (light blue).
    - VERIFY: Input becomes editable again; "Thinking…" indicator disappears.
    - VERIFY: Scroll-to-bottom auto-scrolled (if the conversation overflowed the viewport,
      you see the newest reply).
    - Record: PASS / FAIL + first 100 chars of the reply.

    ### Test 5 — Error card rendering: DISABLED (UI-04)

    - Close the ChatScreen (ESC).
    - On the server console: `/forgebook disable`.
    - Open the inventory, click the "F" button again, type "hi", press ENTER.
    - VERIFY: An error CARD (full-width, NOT a bubble) appears inline in the conversation.
    - VERIFY: The card has a 4-px GRAY left stripe (0xFF808080) — DISABLED color per UI-SPEC.
    - VERIFY: Heading says "ForgeBook is turned off" (i18n key `forgebook.error.disabled.heading`).
    - VERIFY: Body says "A server operator has disabled ForgeBook. Try again later." OR the
      server-emitted humanReadable string "ForgeBook is temporarily disabled by an operator."
    - VERIFY: No toast / chat-line appeared — errors render INLINE in the panel only.
    - On the server console: `/forgebook enable` to restore for later tests.
    - Record: PASS / FAIL + screenshot.

    ### Test 6 — Error card rendering: FORBIDDEN (UI-04)

    - VERIFY: Body explains OP-only state.
    - On the server: `op Player001` to restore for later tests.

    ### Test 7 — Error card rendering: RATE_LIMITED (UI-04)

    - Record: PASS / FAIL / SKIP.

    - Record: PASS / FAIL.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| client runtime → observer | Human verifier observes the live rendering surface for any UI/UX anomalies that code review + unit tests cannot detect |
| client source → manual grep | UI-08 compliance confirmed with a final manual scan to catch any accidental import regressions |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-04-06-01 | Information Disclosure | A stray import of ApiKey sneaked past the CI grep (e.g., via a nested inner class or a commented-out block that later gets uncommented) | mitigate | Test 12's manual grep triples-checks beyond the CI rule — scans the entire client tree (not just .ui/.session) for ApiKey imports AND for .raw() call sites. Dual defense against accidental exposure. |
| T-04-06-02 | Spoofing | A mod-in-the-middle (other Forge mod) inspects the chat UI's in-memory state and reads messages | accept | Defense in depth is Minecraft's OP security model — any mod the user installs can in principle read any other mod's memory. ClientChatSession holds transient conversation; no credentials. Not a realistic threat vector for a text-chat UI. |
| T-04-06-03 | Denial of Service | Very long single message (>32 KB reply) causing wire truncation + visible garbling | accept | Already handled by ChatResponsePacket.encode's writeUtf(reply, 32_000) cap — server truncates at send time. Client sees a complete (truncated) bubble. Test 4 observes a normal reply; oversized-reply edge case is in-scope for Phase 5 README but not a Phase 4 rendering bug. |
| T-04-06-04 | Repudiation | Human UAT report marked PASS but a hidden regression later surfaces | accept | UAT is a point-in-time smoke; regressions are caught by the same automated gates (SCAF-02 + UI-08 + unit tests) on every future change. The UAT file captures the verification date + commit SHA for forensic traceability. |
</threat_model>
